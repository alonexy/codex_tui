# 手机 Web 控制台

本项目提供 Node.js 22+、运行时无第三方依赖的本地控制台。手机真实网络与桌面双端执行仍待验收，当前证据见 [验收记录](mobile-acceptance.md)。

## 两种运行模式

**桌面共享模式**：手机 HTTP → 独立 Web 进程 → 本机 Unix socket → 常驻桥接器 → 桌面启动的同一个 Codex App Server。
桌面原有 stdio 经桥接器转发，两端请求 ID 隔离；执行事件同时发往桌面及手机。
不启动另一个服务来恢复桌面任务，也不直接读写数据库或 rollout。

**独立模式**：`npm start` 自己启动 App Server。只允许访问由该服务创建、登记于
`.codex-phone/threads.jsonl` 的任务；不能操作桌面已有任务。单个端口只允许一个实例。
两个模式不能共用同一桥接 socket；要控制桌面请使用桌面共享模式。

## 日常启动和更新

在项目目录执行：

```sh
npm run web          # 启动 Web，已运行时复用
npm run web:restart  # 只重启 Web，不退出桌面，不中断任务
npm run web:stop     # 只关闭 Web
npm run web:status   # 查看 Web 进程状态
```

桥接器保留任务、回执、事件和待审批请求，Web 只负责页面与认证。
Web 重启后需要重新输入密码，页面会恢复所选任务；不会自动重新发送指令。
Web 可以先于桌面启动，页面会等待桥接连接并自动加载任务。
HTML、CSS、浏览器 JS 修改后刷新即可；Web、HTTP、认证代码或密码变化后运行 `npm run web:restart`。
修改常驻桥接、Broker 或内部协议仍需在任务结束后重新加载桌面。
从旧的单进程实现迁移需要退出桌面一次，新代码无法热替换现有 stdio 连接。

## 初次设置

进入本项目目录后，直接在终端运行：

```sh
npm run desktop
```

它会保留已有密码、缺少时生成密码，并使用固定项目路径启动桌面共享模式。
如果新版桥接已经运行，命令会复用它并确保 Web 启动，不要求退出桌面。
只有首次加载或从旧版迁移时，命令才等待最多 3 分钟；保存工作后 Cmd+Q 完全退出，命令会自动继续。
通过本机桥接接口确认共享模式就绪，并确认 Web 管理服务启动后，才打印“启动成功”。
密码从终端提示的本机文件读取；日志在 `.codex-phone/desktop.log` 和 `.codex-phone/web.log`，可能含本机诊断信息，请勿公开原始日志。
只检查当前状态、不启动 App：`npm run desktop -- --check`。

以下为手动配置方式。

在本项目目录执行以下命令生成访问密码。文件仅本机用户可读，切勿提交或放进 URL。

```sh
mkdir -p .codex-phone
node -e 'require("fs").writeFileSync(".codex-phone/password", require("crypto").randomBytes(24).toString("base64url"), {mode: 0o600, flag: "wx"})'
chmod +x src/bridge.mjs
```

文件已经存在时不要重新生成；打开 `.codex-phone/password`，复制密码到登录页。
也可在本机编辑此文件设置自己的密码，至少 12 个字符、最多 1024 字节，文件权限保留 600。
不要把实际密码发到对话中。文件首尾空白会在服务启动时去除。
修改密码后执行 `npm run web:restart` 生效，同时所有旧会话失效，任务继续运行。

密码只在登录时发送，浏览器不会把它写入 localStorage 或 sessionStorage。服务端使用
scrypt 校验，成功后签发随机会话 Cookie，带 HttpOnly、SameSite=Strict；HTTPS 模式
额外带 Secure 和 __Host- 前缀。Cookie 不能被页面脚本读取。

未登录访问 `/` 会转到 `/login`；控制台 HTML、`/app.js`、所有任务 API 均需要登录。
登录页与公共样式可以被访问，但不会包含任何任务信息。旧 Bearer 令牌接口已移除。
每个来源 IP 在 60 秒窗口内最多进行 5 次密码校验（成功也计数），超出后返回 429 和剩余等待秒数。
缺少密码、非字符串或超长密码不消耗额度；一个来源的失败不会扣除其他来源的额度，成功登录也不会清空其他来源的计数。
全局最多同时执行 2 次 scrypt 校验，最多保留 1024 个活跃来源；资源满时返回 429、Retry-After: 1，不建立全局 60 秒锁定。
默认以 TCP 对端 IP 识别来源，忽略客户端的 X-Real-IP / X-Forwarded-For。同一 NAT 或不传客户端地址的隧道仍共享来源额度；分布式请求或持续占满计算资源仍可能影响登录可用性。
会话最多 8 小时、30 分钟没有请求后过期；点击“锁定并退出”会撤销当前会话。
页面在后台暂停轮询，锁屏久了返回时可能需要重新登录；电脑任务不受影响。

独立模式：

```sh
CODEX_PHONE_PASSWORD_FILE="$PWD/.codex-phone/password" npm start
```

上述命令只启动独立桥接；另一个终端执行 `npm run web`，然后打开 http://127.0.0.1:8787 。服务默认从 ChatGPT.app 内置路径启动 Codex；
可用 `CODEX_REAL_CLI` 指定真实 Codex 可执行文件绝对路径。

## 首次加载桌面共享模式

桌面共享模式使用 `CODEX_CLI_PATH` 覆盖 CLI 启动路径，不依赖桌面 App Server 提供外部监听入口。
这个入口不是稳定公共 API，升级后需重新验收。
无法把桥接器热插入已经建立的 stdio；需要正常退出桌面，再从终端启动。
以下用于首次加载或迁移；已加载新版桥接时不需要重复退出。
若确需重新加载桥接，请先完成活跃任务。

检查桌面已完全退出、独立服务已关闭，然后在本项目目录执行：

```sh
CODEX_CLI_PATH="$PWD/src/bridge.mjs" \
CODEX_PHONE_PASSWORD_FILE="$PWD/.codex-phone/password" \
PATH="$PATH" \
/Applications/ChatGPT.app/Contents/MacOS/ChatGPT
```

手动启动方式还需要另一个终端执行 `npm run web`；推荐直接使用 `npm run desktop` 完成两者。
没有安装开机自启，也没有修改普通桌面图标的启动行为；桌面退出后使用本项目启动命令重新打开。

桌面可执行文件名必须与本机 `CFBundleExecutable` 一致；不同版本可能有不同名称。
桥接器以 `#!/usr/bin/env node` 启动，所以上述终端 PATH 必须能找到 Node.js 22+。
无需替换 App 内文件、修改全局环境、安装插件或更改全局 Codex 配置。
恢复原状：退出这次桌面实例，正常从应用程序目录启动即可。

### 内置浏览器提示无法验证管理员策略

Browser Use 和 Computer Use 会通过同一个 CLI 路径启动辅助 App Server 来读取配置和策略。
桥接器在读取初始化客户端身份后，将 `codex-browser-use`、`codex-computer-use` 转交原生 CLI，
辅助连接不创建手机服务 socket；桌面主连接仍由桥接器管理。原生策略结果与错误原样返回。
旧版把辅助连接当作主连接，因“本机服务已运行”退出，可能表现为“管理员策略无法验证”。
这项修复在下次启动辅助进程时生效，不要求中断桌面任务；旧工具会话仍报错时可重新初始化工具再试。
桌面升级后应同时验证策略读取、实际页面访问及手机连接，不能只根据普通配置请求成功判断浏览器已恢复。

打开控制台后，页面必须显示“桌面共享连接”。选择桌面已有任务，追加一轮，
确认桌面与手机同时看到用户消息、增量输出和完成状态。再验证执行中追加、停止、
两端抢答审批及关闭手机后重连。只有这些验证通过，才可称为桌面实时控制已完成。

## 手机访问

本服务默认监听 `0.0.0.0:8787`。手机不能通过手机自身的 localhost 访问电脑。
把用户自行管理的 HTTPS 隧道/反向代理指向电脑 `127.0.0.1:8787`，并在启动前设置：

```sh
export CODEX_PHONE_ORIGIN="https://你的完整域名"
```

代理需要保留 Cookie、Set-Cookie 和 Origin 请求头，关闭页面与 API 缓存。
所有 POST 请求均检查精确 Origin；推荐公网使用 HTTPS。不要把 App Server 端口暴露公网。
Web 默认监听 `0.0.0.0:8787`，供局域网代理连接；监听地址不是浏览器访问地址。
默认来源仍为 `http://127.0.0.1:8787`；其他来源由 `CODEX_PHONE_ORIGIN` 或 `.codex-phone/access.json` 的 `origin`、`additionalOrigins` 配置。监听所有网卡不会关闭密码验证或来源校验。
非本机 HTTP 默认拒绝；现有 `allowLanHttp` 允许私有 IPv4，`allowHttpOrigins` 可明确批准精确的公网 HTTP 来源，但它本身不会把来源加入允许列表。所有允许来源必须使用同一协议。
HTTP 例外不会加密密码或 Cookie。HTTPS 由部署者另行配置；设置 HTTPS 来源并不让 Node 监听器自动提供 TLS。实际访问地址和可信代理配置只保存在被忽略的 `.codex-phone/access.json` 中，不应复制到公开文档。

如反向代理需要按真实客户端分别限流，在现有 `.codex-phone/access.json` 中增加 `"trustedProxyAddresses": ["代理连接电脑时的实际IP"]`，只支持精确 IP，不支持网段或主机名，默认空数组。
只有 TCP 对端匹配该列表时，登录接口才使用代理传入的单个 `X-Real-IP`；缺失、列表或无效值会拒绝登录。IPv4 与 IPv4-mapped IPv6 使用同一额度。
例如信任 `127.0.0.1` 后，本机浏览器直连且不带该头也会被拒绝，应改为通过代理登录；不要仅为绕过共享额度而信任本机隧道。
代理必须覆盖客户端传入的该头，例如直接面对客户端的 Nginx 使用 `proxy_set_header X-Real-IP $remote_addr;`，不能照搬客户端请求头。多级代理需由部署者配置真实来源链；应用不解析 X-Forwarded-For。
不要把普通客户端地址或不覆盖该头的透明转发端点加入可信列表，否则客户端可以伪造来源绕过限流。未配置可信代理的现有隧道仍可使用，但代理后的用户共享同一来源。
配置或认证代码更新后执行 `npm run web:restart`；只重启 Web，旧登录会话失效，桌面任务继续运行。

历史消息使用 `thread/resume` 的 `excludeTurns: true`，再通过 `thread/items/list` 每页读取 100 项，默认显示最新消息，可加载更早消息。桥接器通过 `capabilities.paginatedHistory` 声明分页支持。已运行的旧桥接在桌面下一次正常启动前继续兼容旧读取方式；仅重启 Web 无法更新桌面桥接白名单。
旧的 CODEX_PHONE_TOKEN_FILE 仍可作为密码文件路径兼容使用，浏览器仍需走新的密码登录流程。
项目不会自动创建隧道、域名或部署；真实手机网络链路需要部署者验证。

## 手机操作

- 登录页支持密码自动填充、显示/隐藏密码及验证中的按钮反馈。
- 输入栏按钮使用统一 Flex 布局，默认 48×48px，窄屏使用 44×44px；发送、停止保持圆形，图标中心对齐。输入区与工具栏分隔，点命令不会自动唤起消息键盘；输入字号至少 16px。
- 发送入口根据状态显示“发送新一轮”或“追加到当前执行”，旁边独立提供停止按钮。
- 提交和任务切换期间禁止重复发送；输入框保留失败的指令，支持继续编辑。
- 附件仅支持现有 PNG/JPEG/WebP 图片，以及文本、Markdown、日志、代码、JSON/CSV 和 PDF、Word、Excel、PPT。文档后缀为 `.pdf/.doc/.docx/.xls/.xlsx/.ppt/.pptx`；不开放通用压缩包、音视频、安装程序或宏启用的 Office 后缀。
- 文本类要求 UTF-8 编码且不含二进制控制字节。Office 除后缀外还检查容器、主文档类型及宏标记；加密、含宏或不支持的复杂旧版容器会明确拒绝，可另存为不含宏的新版格式。格式检查不是完整文档解析或恶意内容扫描。
- 单个普通文件最多 20 MiB，图片沿用 8 MiB；每条消息图片和文件合计最多 10 个、50 MiB，浏览器与服务端均限制。文件采用独立上传接口，原件保持原始字节，消息只携带文件引用，避免将全文或大段 Base64 塞入消息。
- 图片保留缩略图，其他附件显示文件名、大小和上传状态，可在发送前移除；失败保留草稿，重试复用已成功上传的附件。草稿仍按会话保存在当前页面内存，刷新或关闭页面不会持久保存未发送内容。
- 文件引用交给同一个桌面任务按需读取。文档文字、表格提取及扫描件识别由任务按需使用可用工具处理，上传本身不解析、不执行文件，也不扩大任务权限；加密或损坏文档、缺少解析/OCR工具等情况仍可能无法读取。
- 已登记上传文件的历史附件可通过需登录的接口下载，下载按附件处理，不在页面执行 HTML 或源码；普通本机路径不会因出现在消息中就获得下载入口。原件保存在本项目私有状态目录，使用随机存储名，不覆盖项目文件。
- 上传原件暂不自动清理，以便历史任务继续读取；50 MiB 为单条消息限制，不是磁盘总容量限制。附件接口和新增页面模块更新后，运行 `npm run web:restart` 并重新登录即可，不需要重启桌面 App。
- 新建会话只需选择已同步的桌面项目，会话使用该项目配置的全部目录，可跨组成部分工作。“高级选项：起始目录”仅调整初始工作位置，不会缩小项目范围；也可手动填写项目外的单个目录。
- 新建时可填写会话名称，留空沿用默认命名。创建与命名是两个桌面接口调用：会话创建成功后，若命名失败，只需重试命名，不要重新创建。
- 侧栏每条会话提供铅笔图标的重命名入口，可直接修改未选中的会话；图标保留操作提示及无障碍名称。弹窗预填现有名称，保存后更新列表、当前标题及本地收藏。名称通过桌面原生接口保存，桌面名称更新事件也会同步到手机；`/rename 新名称` 入口仍可使用。
- 侧栏归档图标用于归档会话，确认后调用桌面原生 `thread/archive`，不删除记录。在“已归档”列表可通过 `thread/unarchive` 恢复，然后继续会话。运行中或等待批准的会话需先处理完毕；失败及结果待确认时保留原状态，使用原提交回执查询，不自动重复归档。
- 若桥接重启导致归档回执丢失，先在桌面或归档列表核对该会话的实际状态，再确认清除本地待确认记录；清除仅解除提交锁定，不会重发、撤销或恢复会话。
- 归档功能需要桥接声明 `capabilities.taskArchive`。旧桥接显示不可用原因；更新 Broker 后需等任务结束，再正常退出并重新启动桌面，仅刷新网页或重启 Web 不会更新此能力。
- 任务列表支持本地筛选、历史标题搜索和项目限定，按项目分组；普通列表与已归档列表分别搜索、分页。普通列表收藏优先显示，归档会话从普通列表及本地收藏移除。任务运行状态随连接更新，断线显示等待同步。
- 项目展开、收藏任务的最小元数据、各项目最近起始目录保存在本浏览器 localStorage；不与桌面收藏同步。浏览器禁用存储时退回内存，不影响操作。新建前显示所属项目与目录数量，无效的已记忆起始目录会回退到当前项目有效目录。创建时原生 `projectId` 记录归属，`runtimeWorkspaceRoots` 传入项目全部目录；此次调整适用于新建会话，已有会话沿用创建时的范围。
- 对话默认展开，按用户与助手分条阅读；每轮的执行命令、文件修改、工具详情及明确标注的中间进度归入一个“执行过程”折叠区，最终回复显示在外。旧记录未标注消息阶段时保留正文，避免误隐藏回复。
- 执行过程默认收起，执行中展示当前动作，完成后显示可确认的整轮耗时与文件修改摘要；缺少数据时省略对应统计。用户主动展开后，实时更新及完成不会强制收起。等待批准、需要回答和执行异常继续在折叠区外提示。
- 支持标题、粗体、行内代码、代码复制、基础列表、网页链接和表格；并非完整 CommonMark 实现。
- 左上角打开项目/任务侧栏；草稿按任务暂存在页面内存，刷新或关闭后丢失。收藏和目录偏好可通过清除此站点数据删除。
- 命令菜单按任务、目标、模型与状态分类，不可用命令显示原因；模型和推理强度通过选择器设置，重命名使用标题表单，取消或失败保留消息草稿和附件。原 `/命令 参数` 输入仍可使用。
- 模型选项读取桌面 Codex 上次同步的本机目录，只展示可选模型；推理强度随所选模型联动。目录无法读取时可重试，不要求手填型号，也不猜测支持范围。
- 模型弹窗每次打开都会只读获取当前会话的模型与强度，并接收桌面设置更新；当前值未知时明确提示，不用目录默认值代替。已保存但未发送的选择单独标记为下轮设置；确认发送成功后清除该覆盖，发送失败则保留，回执未知时标记待确认。
- 模型和强度设置用于后续新一轮，通过原生 `turn/start` 的 `model`、`effort` 参数提交；执行中追加消息不会改变本轮设置。模型默认强度会明确提交，避免继承上一模型的强度。
- 输入栏的模式选择器或 `/plan`、`/default` 可选择计划或执行模式；切换用于下一轮消息，执行中追加只延续当前轮次。模式使用原生 `collaborationMode` 参数，并与本轮选定的模型、推理强度一起提交，不通过拼接提示词模拟。打开任务会主动同步模式：优先使用桌面设置，其次只读任务记录中的轮次模式，分别标注本轮或最近一轮。旧版驻留桥接也可读取轮次记录，无需为此重启桌面。最近一轮的模式不能代表桌面尚未发送的选择，也不会静默覆盖发送设置。没有有效记录时显示「选择模式」。计划模式是协作行为设置，不是文件系统只读权限。
- 计划提问使用输入栏上方的底部停靠卡片，与消息输入框保持独立表单：直接点选编号答案或自行填写，多道题可前后切换并保留答案，最后统一提交。长题目在卡片内部滚动，切题和提交按钮保持可见；键盘弹出时按可见区域调整高度。收起后保留「待回答 · 共 N 题」入口，展开恢复答案。选择答案、切换题目和收起卡片都不会自动发送或批准；等待回答状态会保留到请求实际结束。普通执行和文件授权审批仍显示在原位置。
- 异步提问也使用底部卡片，读取助手消息中的结构化问题，不把普通文字列表当作交互请求。异步答案按桌面格式作为用户消息发送：运行中追加到当前轮次，空闲时开始新一轮；不走审批答复接口，也不清空消息输入框中的草稿或附件。历史按问题 ID 关联回答，显示问题摘要和答案，兼容桌面已回答的记录；无法解析的内容保留原文。提交结果未知时先查询回执，不自动重发。
- 异步问题卡片在60秒未操作后自动收起，保留「待回答」入口和本页已填答案；点击、切题、滚动重新计时，自填框聚焦或提交待确认时暂停计时。展开后可以继续回答，不会因超时自动发送、批准或跳过问题；同步提问和普通审批不自动收起。
- 模式入口位于输入框外上方，以紧凑胶囊显示；点击后在页面内展开「执行」「计划」两项，展开区参与布局，不覆盖来源提示或输入框。已确认处于计划模式时显示「计划」和紫色边框、底色。点击 × 取消尚未发送的计划选择；若当前已经在计划模式，则将下一轮设为执行。尚未发送的选择会标记「下轮」，不会提前改变当前模式外观。
- 审批展示命令、目录及原因；建议答案可点选，提交时禁用重复操作。
- 当前会话等待批准或回答时，输入区附近显示处理入口，阅读最新消息时也可看到；点击定位对应请求，不会自动打断阅读或输入。
- 其他会话待处理时，侧栏入口、所属项目及会话显示提醒；侧栏的待处理列表独立于搜索筛选，可打开尚未加载到普通列表的会话。桌面或手机处理后随快照更新清除提醒。
- 桌面报告正在等待、但手机没有对应可处理请求时，显示需在桌面处理；不把普通“批准”快捷消息当成接口授权。断线时保留提醒并标记待核对，重新连接确认前不能提交审批。
- 停止任务显示等待状态；等待停止回执时禁用发送、新建和任务切换。
- 支持系统放大文字与减少动画；窄屏自然换行，低高度时输入区恢复普通文档流。

更新包含新增页面模块或模型目录接口的版本后，执行 `npm run web:restart`，再刷新并重新登录；只重启 Web，不必退出桌面 App。

## 连接恢复与发送回执

输入栏显示发送中、已接收、执行中、已完成/停止、连接中断或结果待确认。网络恢复、页面重新可见时重新加载所选任务和历史，避免只显示断线前的内容。
写操作发出前在 sessionStorage 保存提交 ID、方法、任务 ID 和时间；新建及重命名还会保留所请求的名称，用于结果确认后的命名恢复，不保存消息正文或附件。无法保存回执时先拒绝发送并提示。刷新后仍用同一提交 ID 查询原回执，绝不自动重发控制请求。
新建成功、命名尚未完成时，同一标签页还会暂存会话 ID、请求名称、工作目录及项目 ID；刷新后继续为这条会话命名，命名完成或明确取消后清除。它不会保存消息内容，也不会同步到其他设备。
结果待确认时禁止继续发送或其他依赖写操作；可以点“查询发送结果”。服务明确返回完成或失败后解除；如果桥接重启后回执丢失，必须先核对任务历史，再手动清除记录。清除不会撤销已经执行的指令。
连接恢复后已接收消息会补齐到历史；当前页面仍持有对应草稿时清理已确认发送的草稿。任务运行期间仍能追加指令，停止入口保持独立。

## 登录设备与安全记录

侧栏点击“登录设备与安全记录”可查看当前有效会话的浏览器/系统类别、登录来源、登录时间、最近访问和到期时间，并撤销单个或全部会话。设备类别来自浏览器标识，只用于辨认，不是硬件身份认证。同一手机多次登录可能显示多个会话。
设备列表使用独立公开 UUID，不暴露 Cookie 会话令牌。列表、撤销和安全记录接口均要求有效登录与精确 Origin；撤销立即禁止该会话后续访问，不停止已运行的桌面任务。撤销当前或全部设备会返回登录页。
安全记录仅包含固定字段：时间、来源 IP、浏览器/系统类别、公开会话 ID、动作和结果，不包含密码、Cookie、任务正文、指令参数或错误原文。记录登录、撤销、控制提交与审批处理，不将历史读取当作控制操作；“已接收”并不等于模型任务最终执行成功。
Web 默认保存到 `.codex-phone/security-audit.jsonl`，权限 600；当前及上一份日志各不超过 256KiB，内存保留最近 300 条。失败/拒绝事件按来源和动作采样，并限制每分钟写入量，界面显示省略计数和落盘不可用状态。这是有界运行记录，不是不可篡改审计系统。

前端改动刷新即可；本次设备管理涉及 Web 后端，运行 `npm run web:restart` 后生效，已有登录会话会失效，桌面任务继续运行。HTTPS 及真实代理配置仍由部署者另行处理。

## 行为和当前限制

- 手机每秒补读一次事件。页面关闭或 Web 重启后 App Server 继续执行；桌面退出则桥接退出，Web 保持运行并等待连接。
- 内部 socket 默认位于 `.codex-phone/ipc/`，目录权限 700、socket 权限 600，仅供当前系统用户使用，不暴露网络端口。同一系统用户属于信任边界。
- 默认状态目录固定为本项目 `.codex-phone`；可用 `CODEX_PHONE_STATE_DIR` 和 `CODEX_PHONE_SOCKET` 配置，Web 与桥接必须使用相同配置。
- 新建任务使用当前 Codex 默认模型、配置和权限。执行中不自动排队，使用明确的 steer。
- 命令回执在桥接进程内保存，每次运行最多 5000 次提交；相同提交 ID 不会重复执行。
- 连接异常不会自动重发。浏览器保留未知提交 ID；先刷新历史核对，再手动清除记录。
- 回执与事件未持久化，桥接进程重启后需读取 Codex 历史核对；不会自动重放未完成指令。
- 独立模式用 `.codex-phone/run.lock` 防止同一状态目录并发启动。异常强制退出可能留下锁；
  只有确认相关服务进程已结束后，才手动删除这个空目录。
- 事件缓存最近 1000 条，手机显示最近 80000 字符；游标断档时重新读取所选任务历史。
- 手机支持单次命令/文件审批及用户输入。动态工具及其他审批由桌面处理；独立模式遇到
  未支持的服务请求可能停等，须停止该轮。模型登录、插件登录等仍在本机完成。
- Web 与桌面共享同一连接的能力由模拟测试覆盖；桌面实际行为、升级兼容性未验证。
- 没有使用截图、OCR、图像定位或微信操作。
